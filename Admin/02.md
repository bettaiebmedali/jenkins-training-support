TP Administration Jenkins 1
Agent Jenkins Offline / en erreur JNLP ou SSH
🎯 Objectif

Diagnostiquer, réparer et remettre en ligne un agent Jenkins cassé.

🧩 Situation réelle

Un agent Jenkins Linux est marqué :

Agent is offline  
No connection to agent  
Waiting for next available executor


Les pipelines sont bloqués.

🛠️ Étapes à réaliser
### 1. Vérifier l’état du service agent

Sur la machine agent :

systemctl status jenkins-agent
journalctl -u jenkins-agent -n 50

2. Redémarrer l’agent
systemctl restart jenkins-agent

3. Vérifier la connectivité réseau

Depuis le master :

ping <agent-ip>
nc -z <agent-ip> 50000

4. Vérifier la configuration dans Jenkins

Dans Manage Jenkins → Nodes :

Vérifier la clé secrète JNLP

Vérifier le bon chemin du workDir

5. Reconnecter manuellement

Jenkins → Node → "Reconnect"

✔ Résultat attendu

L’agent apparaît Online et exécute à nouveau les pipelines.

Agent is connected and ready

find /var/lib/jenkins/jobs/*/builds -type d -mtime +15 -exec rm -rf {} \;

Keep 20 builds
Keep artifacts: 10 days

5. Si Docker est utilisé : clean
docker system prune -af

✔ Résultat attendu

Le disque retombe sous 70 % et Jenkins redevient stable.

TP Administration Jenkins 4
Credentials mal gérés (mots de passe exposés)
🎯 Objectif

Sécuriser les secrets et corriger les pipelines dangereux.

🧩 Situation réelle

Un développeur a mis dans son Jenkinsfile :

sh 'docker login -u toto -p password123'

🛠️ Étapes
1. Créer un credentials sécurisé

Credentials → System → Global :

ID : docker-pass

Type : Secret Text

2. Corriger le Jenkinsfile
withCredentials([string(credentialsId: 'docker-pass', variable: 'PASS')]) {
    sh 'echo $PASS | docker login -u toto --password-stdin'
}

3. Scanner Jenkins pour secrets exposés
grep -R "password" /var/lib/jenkins/jobs/

✔ Résultat

Plus aucun mot de passe n’est visible en clair.

TP Administration Jenkins 9
Sauvegarde complète & restauration Jenkins
🎯 Objectif

Sauvegarder Jenkins et restaurer une instance en cas de crash.

🧩 Contexte réel

Le dossier jobs/ est supprimé → plus aucun pipeline.

🛠️ Étapes
1. Sauvegarde manuelle
tar czf jenkins-backup.tar.gz \
  /var/lib/jenkins/jobs \
  /var/lib/jenkins/secrets \
  /var/lib/jenkins/plugins \
  /var/lib/jenkins/config.xml \
  /var/lib/jenkins/credentials.xml

Sur un nouveau serveur :

systemctl stop jenkins
tar xzf jenkins-backup.tar.gz -C /var/lib/jenkins
systemctl start jenkins

✔ Résultat

Jenkins retrouve exactement son état initial.
