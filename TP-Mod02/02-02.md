# Pipeline avancé ⚡

## Contexte / Storytelling

La startup **GFP Tech** développe une application Java basée sur **Maven**.

Au départ, le pipeline Jenkins était très simple : il exécutait directement Maven sur le serveur Jenkins.

Mais plusieurs problèmes apparaissent :

- le pipeline doit pouvoir construire différentes branches Git ;
- le développeur doit pouvoir choisir l'environnement cible ;
- le build ne doit pas dépendre de la version de Java/Maven installée sur le serveur Jenkins ;
- les tests doivent pouvoir être exécutés indépendamment du build ;
- le pipeline doit gérer proprement les échecs ;
- l'environnement de compilation doit être isolé dans Docker.

Vous allez donc faire évoluer progressivement le pipeline pour obtenir un pipeline Jenkins plus proche d'un contexte réel.

---

## Objectifs pédagogiques

À la fin de ce TP, vous serez capable de :

- utiliser des paramètres Jenkins ;
- utiliser un paramètre pour sélectionner réellement une branche Git ;
- utiliser un paramètre pour sélectionner un profil Maven ;
- travailler avec un projet Maven situé dans un sous-répertoire du dépôt ;
- désactiver le checkout automatique de Jenkins ;
- réaliser un checkout Git explicite ;
- exécuter des stages en parallèle ;
- gérer les erreurs et les résultats du pipeline ;
- utiliser un agent Docker pour isoler l'environnement de build ;
- utiliser Java et Maven directement depuis une image Docker ;
- conserver le cache Maven grâce à un volume `.m2`.

## Étapes détaillées
# 1. Ajouter des paramètres au pipeline

L'objectif est de permettre à l'utilisateur de choisir :

la branche Git à construire ;
l'environnement Maven.

Les environnements disponibles sont :
```text
dev
staging
prod
```
Commencez avec :
```text
pipeline {

    agent any

    parameters {

        string(
            name: 'BRANCH_NAME',
            defaultValue: 'main',
            description: 'Branche à construire'
        )

        choice(
            name: 'ENV',
            choices: ['dev', 'staging', 'prod'],
            description: 'Environnement cible'
        )
    }

    stages {

        stage('Build') {

            steps {

                echo "🛠️ Build de la branche ${params.BRANCH_NAME} pour ${params.ENV}"

                sh "mvn clean compile -P${params.ENV}"
            }
        }

        stage('Test') {

            steps {

                echo '✅ Exécution des tests unitaires...'

                sh 'mvn test'
            }
        }
    }
}
```
# Test

Lancer le pipeline avec :
```text
BRANCH_NAME = feature-test
ENV = dev
```
# Observez le message :

🛠️ Build de la branche feature-test pour dev
Attention

À ce stade, le paramètre BRANCH_NAME est uniquement utilisé dans le message.

Il ne change pas réellement la branche Git checkoutée.

C'est une erreur fréquente dans les pipelines Jenkins.

## 3. Gérer le projet Maven dans un sous-répertoire

Notre projet n'est pas à la racine du dépôt.

Nous avons :
```text
jenkins-pipeline/
└── jenkins-param-lab/
    ├── pom.xml
    ├── Jenkinsfile
    └── src/
```
Si Jenkins exécute :
```text
mvn clean compile
```
depuis :

/var/lib/jenkins/workspace/m01

Maven ne trouve pas le pom.xml.

Nous allons donc utiliser dir() :
```text
stage('Build') {

    steps {

        dir('jenkins-param-lab') {

            echo "🛠️ Build de ${params.BRANCH_NAME} pour ${params.ENV}"

            sh "mvn clean compile -P${params.ENV}"
        }
    }
}
```
Même principe pour les tests :
```text
stage('Test') {

    steps {

        dir('jenkins-param-lab') {

            echo '✅ Exécution des tests unitaires...'

            sh 'mvn test'
        }
    }
}
```
Point pédagogique

dir() permet de changer le répertoire de travail uniquement pour les étapes qu'il contient.

## 4. Désactiver le checkout automatique

Avec un pipeline déclaratif, Jenkins réalise normalement automatiquement :

Declarative: Checkout SCM

Or nous voulons contrôler nous-mêmes le checkout avec :
```text
git(
    branch: params.BRANCH_NAME,
    url: 'https://github.com/bettaiebmedali/jenkins-pipeline.git'
)
```
Nous ajoutons donc :
```text
options {
    skipDefaultCheckout(true)
}
```
Le pipeline commence alors ainsi :
```text
pipeline {

    agent any

    options {
        skipDefaultCheckout(true)
    }

    parameters {
        ...
    }

    stages {
        ...
    }
}
```
Le checkout devient donc totalement explicite.

## 5. Ajouter des étapes parallèles

Nous allons maintenant exécuter plusieurs contrôles simultanément.

             ┌── Unit Tests
Checkout ────┤
             └── Maven Verify

Ajoutez :
```text
stage('Quality Checks') {

    parallel {

        stage('Unit Tests') {

            steps {

                dir('jenkins-param-lab') {

                    echo '🧪 Tests unitaires'

                    sh 'mvn test'
                }
            }
        }

        stage('Maven Verify') {

            steps {

                dir('jenkins-param-lab') {

                    echo '🔍 Vérification Maven'

                    sh 'mvn verify -DskipTests'
                }
            }
        }
    }
}
```
Question

Observez l'affichage Jenkins.

Les deux stages doivent apparaître simultanément :

Quality Checks
├── Unit Tests
└── Maven Verify
Question pédagogique

Pourquoi utiliser parallel ?

Pour exécuter plusieurs tâches indépendantes simultanément et potentiellement réduire le temps total du pipeline.

## 6. Ajouter la gestion des erreurs

Nous allons maintenant observer le comportement du pipeline lorsqu'une étape échoue.

Ajoutez :
```text
post {

    success {

        echo '🎉 Pipeline terminé avec succès !'
    }

    failure {

        echo '❌ Le pipeline a échoué !'
    }

    always {

        echo '📋 Fin du pipeline.'
    }
}
```
Le pipeline pourra donc distinguer :
```text
SUCCESS
FAILURE
Test
```
Provoquez volontairement une erreur :

sh 'mvn commande-inexistante'

Puis observez :

❌ Le pipeline a échoué !

Remettez ensuite la bonne commande.

## 7. Exécuter le pipeline dans Docker

Nous voulons maintenant éviter que le pipeline dépende directement du Java/Maven installé sur le serveur Jenkins.

Nous allons utiliser l'image :

maven:3.9.9-eclipse-temurin-21

Cette image fournit :

Java 21
Maven 3.9.9

L'agent devient :
```text
agent {
    docker {
        image 'maven:3.9.9-eclipse-temurin-21'
    }
}
```
Le build est alors exécuté dans un conteneur Docker.

## 8. Ajouter le cache Maven

Lors du premier test avec l'agent Docker, Maven peut rencontrer :

Could not create local repository at /.m2/repository

Nous allons donc configurer un volume pour permettre au conteneur d'utiliser le cache Maven de Jenkins.

Sur le serveur Jenkins :

sudo mkdir -p /var/lib/jenkins/.m2
sudo chown -R jenkins:jenkins /var/lib/jenkins/.m2

Puis dans le Jenkinsfile :
```text
agent {
    docker {
        image 'maven:3.9.9-eclipse-temurin-21'
        reuseNode true
        args '-v /var/lib/jenkins/.m2:/var/maven/.m2 -e HOME=/var/maven'
    }
}
```
Le fonctionnement devient :
```text
Serveur Jenkins
      │
      │ /var/lib/jenkins/.m2
      │
      ▼
┌──────────────────────────────┐
│ Docker Maven                 │
│                              │
│ HOME=/var/maven              │
│                              │
│ /var/maven/.m2               │
│       │                      │
│       ▼                      │
│ Maven local repository       │
└──────────────────────────────┘
```
L'intérêt est double :

Maven peut écrire dans son repository ;
les dépendances téléchargées sont conservées entre les builds.
## 9. Pipeline final

Voici le pipeline complet :
```text
pipeline {

    agent {
        docker {
            image 'maven:3.9.9-eclipse-temurin-21'
            reuseNode true
            args '-v /var/lib/jenkins/.m2:/var/maven/.m2 -e HOME=/var/maven'
        }
    }

    options {
        skipDefaultCheckout(true)
    }

    parameters {

        string(
            name: 'BRANCH_NAME',
            defaultValue: 'main',
            description: 'Branche à construire'
        )

        choice(
            name: 'ENV',
            choices: ['dev', 'staging', 'prod'],
            description: 'Environnement cible'
        )
    }

    stages {

        stage('Checkout') {

            steps {

                echo "📥 Checkout de la branche ${params.BRANCH_NAME}"

                git(
                    branch: params.BRANCH_NAME,
                    url: 'https://github.com/bettaiebmedali/jenkins-pipeline.git'
                )
            }
        }

        stage('Build') {

            steps {

                dir('jenkins-param-lab') {

                    echo "🛠️ Build de ${params.BRANCH_NAME} pour ${params.ENV}"

                    sh 'echo "HOME=$HOME"'
                    sh 'java -version'
                    sh 'mvn -version'

                    sh "mvn clean compile -P${params.ENV}"
                }
            }
        }

        stage('Quality Checks') {

            parallel {

                stage('Unit Tests') {

                    steps {

                        dir('jenkins-param-lab') {

                            echo '🧪 Tests unitaires'

                            sh 'mvn test'
                        }
                    }
                }

                stage('Verify') {

                    steps {

                        dir('jenkins-param-lab') {

                            echo '🔍 Vérification Maven'

                            sh 'mvn verify -DskipTests'
                        }
                    }
                }
            }
        }
    }

    post {

        success {

            echo '🎉 Pipeline terminé avec succès !'
        }

        failure {

            echo '❌ Le pipeline a échoué !'
        }

        always {

            echo '📋 Fin du pipeline.'
        }
    }
}
```
