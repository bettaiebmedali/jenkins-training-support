# TP Chapitre 2 – Pipeline avancé ⚡

## Contexte / Storytelling
La startup GFP Tech se développe et plusieurs développeurs travaillent sur le projet.  
Il devient nécessaire d’introduire **des pipelines plus avancés** : paramètres, parallélisation, gestion des erreurs et exécution dans des environnements Docker.  
Vous allez améliorer le pipeline simple pour qu’il supporte plusieurs scénarios et conditions réelles.

---

## Objectifs pédagogiques
- Ajouter des **paramètres de pipeline** pour plus de flexibilité.  
- Implémenter des **stages parallèles** pour gagner du temps.  
- Ajouter la **gestion des erreurs** dans le pipeline.  
- Exécuter les étapes du pipeline dans **Docker** pour isoler l’environnement.

---

## Prérequis techniques
- Jenkins avec pipeline simple existant (Chapitre 1).  
- Docker installé sur le Master ou les agents Jenkins.  
- Projet Maven de base dans GitLab.  

---

## Étapes détaillées

### **1. Ajouter des paramètres au pipeline**
Modifier le `Jenkinsfile` pour inclure des paramètres :

```groovy
pipeline {
    agent any
    parameters {
        string(name: 'BRANCH_NAME', defaultValue: 'main', description: 'Branche à construire')
        choice(name: 'ENV', choices: ['dev', 'staging', 'prod'], description: 'Environnement cible')
    }
    stages {
        stage('Build') {
            steps {
                echo "🛠️ Build de la branche ${params.BRANCH_NAME} pour ${params.ENV}"
                sh "mvn clean compile -P${params.ENV}"
            }
        }
        stage('Test') {
            steps {
                echo '✅ Exécution des tests unitaires...'
                sh 'mvn test'
            }
        }
    }
}
```

### **2. Ajouter des stages parallèles**
Modifier le pipeline pour exécuter **tests unitaires et analyse statique en parallèle** :

```groovy
stage('Parallel Steps') {
    parallel {
        stage('Unit Tests') {
            steps {
                sh 'mvn test'
            }
        }
        stage('Static Analysis') {
            steps {
                sh 'mvn sonar:sonar'
            }
        }
    }
}
```

### **3. Ajouter la gestion des erreurs**
Utiliser `post` pour notifier en cas d’échec :

```groovy
post {
    failure {
        echo "⚠️ Pipeline échoué !"
        mail to: 'team@gfptech.com', subject: "Build Failed", body: "Pipeline échoué sur ${env.BRANCH_NAME}"
    }
}
```

### **4. Exécuter le pipeline dans Docker**
1. Créer un agent Docker dans Jenkins :

```groovy
agent {
    docker {
        image 'maven:3.9.0-openjdk-17'
        args '-v /root/.m2:/root/.m2'
    }
}
```
2. Lancer le pipeline et vérifier que toutes les étapes s’exécutent dans le container Docker.

### **5. Tester le pipeline**
1. Déclencher le pipeline avec différents paramètres (`BRANCH_NAME` et `ENV`).  
2. Observer les étapes parallèles et vérifier que les notifications fonctionnent en cas d’échec.  
3. Vérifier que Docker est utilisé pour toutes les étapes du build.
