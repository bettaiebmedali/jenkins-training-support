# TP Chapitre 9 – Intégration Sonar, Nexus et Docker 🏗️

## Contexte / Storytelling
La startup GFP Tech a maintenant des pipelines multibranch et une gestion GitFlow en place.  
Pour renforcer la **qualité, la sécurité et la distribution des artefacts**, il est temps d’intégrer **SonarQube, Nexus et Docker** dans le pipeline.  
L’objectif est de construire, analyser, stocker et déployer automatiquement vos artefacts.

---

## Objectifs pédagogiques
- Ajouter l’analyse de code avec **SonarQube** dans le pipeline Jenkins.  
- Publier les artefacts Maven sur **Nexus**.  
- Construire et pousser des images **Docker** automatiquement.  
- Intégrer toutes ces étapes dans le pipeline multibranch existant.  

---

## Prérequis techniques
- Jenkins avec pipelines Chapitre 1 à 8.  
- SonarQube accessible avec token.  
- Nexus Repository Manager configuré avec un repository Maven.  
- Docker installé et configuré pour push/pull.  
- Projet Maven prêt avec tests unitaires.

---

## Étapes détaillées

### **1. Intégration SonarQube**
1. Installer le plugin **SonarQube Scanner** dans Jenkins.  
2. Configurer SonarQube dans **Manage Jenkins → Configure System** avec token.  
3. Ajouter un stage dans le `Jenkinsfile` :

```groovy
stage('SonarQube Analysis') {
    environment {
        SONAR_HOST_URL = 'http://sonarqube:9000'
        SONAR_AUTH_TOKEN = credentials('sonar-token')
    }
    steps {
        sh "mvn sonar:sonar -Dsonar.projectKey=demo-app -Dsonar.host.url=${SONAR_HOST_URL} -Dsonar.login=${SONAR_AUTH_TOKEN}"
    }
}
```

### **2. Publier les artefacts sur Nexus**
1. Configurer les credentials Nexus dans Jenkins (`nexus-credentials`).  
2. Ajouter un stage pour publier les artefacts :

```groovy
stage('Publish to Nexus') {
    steps {
        sh """
        mvn deploy -DaltDeploymentRepository=nexus::default::http://nexus:8081/repository/maven-releases/
        """
    }
}
```

### **3. Construire et pousser Docker**
1. Créer un `Dockerfile` dans le projet si pas encore existant :

```dockerfile
FROM openjdk:17-jdk
COPY target/demo-app.jar /app/demo-app.jar
WORKDIR /app
ENTRYPOINT ["java", "-jar", "demo-app.jar"]
```

2. Ajouter un stage Docker dans le pipeline :

```groovy
stage('Build Docker Image') {
    steps {
        script {
            def imageTag = "gfptech/demo-app:${env.BUILD_NUMBER}"
            sh "docker build -t ${imageTag} ."
            sh "docker push ${imageTag}"
        }
    }
}
```

### **4. Intégrer le tout dans le pipeline multibranch**
1. Vérifier que le pipeline détecte toutes les branches.  
2. Configurer les étapes conditionnelles selon GitFlow :  
   - Feature branches : build + tests + SonarQube  
   - Release branches : build + tests + SonarQube + Nexus + Docker staging  
   - Main : build + tests + SonarQube + Nexus + Docker prod

### **5. Tester le pipeline**
1. Créer un commit sur une feature branch et vérifier :  
   - Build Maven OK  
   - Tests OK  
   - Analyse SonarQube exécutée
2. Créer un release branch et vérifier publication sur Nexus et build Docker.  
3. Vérifier la cohérence des artefacts et images Docker.

---

## Livrable final
- Pipeline multibranch complet intégrant :  
  - Build et tests Maven  
  - Analyse SonarQube  
  - Publication sur Nexus  
  - Build et push Docker  
- Artefacts et images Docker disponibles pour tous les environnements.
